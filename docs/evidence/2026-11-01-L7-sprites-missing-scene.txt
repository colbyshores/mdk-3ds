how the archive was made to fail: a symlink farm, not a deleted file. Deleting
       TRAVSPRT.BNI would also remove the data marker (mdk_core/src/formats/
       mdk_data.cpp:13, kMdkDataMarker), so the whole data tree would read as absent
       and the level would never load -- the wrong path entirely. Instead every entry
       of MDK/ and MDK/TRAVERSE/ is symlinked into a scratch tree EXCEPT
       TRAVSPRT.BNI, which is a real 4-byte file. The marker exists, data.found()
       is true, the read succeeds, and Bni::parse rejects it: ArchiveIndex::read
       refuses a file too short to hold a header and an entry count. Two overlapping
       guards do that independently, which is measured and recorded in
       tests/scripts/archive_guard_tests.cpp.

what makes this more than a screenshot: the mechanism is now pinned by a test that
  runs in the gate with no game data at all -- tests/scripts/archive_guard_tests.cpp,
  run from vm_tests main() BEFORE its data check, printing PASS ArchiveIndexGuards.
  It pins that a short archive does not parse, that a zero-filled archive parses as a
  legal EMPTY archive (the guard is about truncation, not content, and the C# can
  legitimately produce an archive with no such entry), and that a well-formed one-entry
  archive parses so the first case is not satisfied by a parse that rejects everything.
  Its falsification is recorded in docs/PROGRESS_LOG.md and is NOT a one-line revert:
  two overlapping guards each reject a 4-byte file on their own, so deleting one prints
  PASS and only deleting both prints FAIL.
