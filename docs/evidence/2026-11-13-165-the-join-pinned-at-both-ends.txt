3. WHAT B12 PINS NOW
-----------------------------------------------------------------------------
The rule is one JOIN read off the record that is PUSHED, and its mirror on the
free side. Not a token, and not a spelling.

(a) THE PUSHED RECORD CARRIES BOTH FIELDS. The helper's own `VkDescriptorSet`
    parameter is read from its signature; the pushed value is resolved, and
    BOTH fields must be filled from it before the push:
      - a named local: `<rec>.set = <param>;` and
        `<rec>.safeFrame = <x>->frameIndex + kFramesInFlight;`, both BEFORE
        the `push_back`;
      - a record built at the call: first field `<param>`, second that same
        boundary.
    The deadline must be EXACTLY `frameIndex + kFramesInFlight` with nothing
    after it — that is what still kills review-9 F1 mutant 3 (`- 1`), which is
    why the exactness moved INTO the join instead of staying a separate regex.
(b) THE FREE HANDLES THE ENTRY IT TESTED. The entry whose `.safeFrame` is
    compared is read from the comparison itself; the handle handed to
    `vkFreeDescriptorSets` must be that entry's `.set`, either named in place
    or copied out of it. `r->retiringSets.back().set` fails: it frees a set
    whose frame was never proven finished (AGENTS P3) and leaks the entry
    erased in its place.
(c) THE LOSS IS COUNTED AND THE COUNT IS TOLD. The increment must sit inside a
    `!= VK_SUCCESS` block in `settleRetired` — not above the test, which counts
    frees that succeeded, and not inside a `refused(` call, which dedups and
    would count sentences instead of sets. The total must be printed from
    `mdk_render_destroy` and guarded by a non-zero test on the counter, so a
    run that lost nothing does not report a loss.
(d) THE DROP-SITE IDENTITY IS TRACED, NOT MATCHED. The second argument of
    `retireDescriptorSet` is resolved to a cache slot, directly or through a
    named local initialised from that slot, and the slot it names must be the
    slot the loop removes — swap-pop or `erase(begin() + i)`.

4. THE PROBES, AND THE PROBE THAT CAUGHT THIS BATCH'S OWN FIX BEING WRONG
-----------------------------------------------------------------------------
An arm proves a rule is SENSITIVE. A probe proves it is not merely sensitive to
a SPELLING, which is what review-10 F5 is about. Three refactors that PRESERVE
the rule now ship in the file and must stay green; the file fails if any of
them reddens. This mechanism already exists in `panel_geom_test.sh` and is
lifted rather than reinvented.

  probe                          what it rewordes
  ------------------------------ ---------------------------------------------
  named local at the drop site   the handle lifted into a local
  erase instead of the swap-pop  the other pop, same slot removed
  aggregate record at the push   the retire record built at the call

The third one is the honest note in this batch. The first version of the new
join rule accepted an aggregate at the push but a SEPARATE older sub-rule
still demanded a literal `safeFrame = ...;` line, so the aggregate refactor —
a correct program — was reddened by the fix that was supposed to stop
reddening correct programs. Measured: `f5c: RED`. The exactness requirement
was then moved into the join, where it reads the deadline off whichever record
is pushed, and all three probes went green. A rule that reddens an honest edit
gets worked around, not obeyed; that is the whole content of F5 and it took a
probe to catch it in the remedy for F5.
