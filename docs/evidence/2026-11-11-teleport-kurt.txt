§5. WHAT THIS BATCH DOES NOT EVIDENCE, AND ONE DIVERGENCE IT FOUND
--------------------------------------------------------------------------------
* THE PORT HAS TWO ARENASPACES WHERE THE C# HAS ONE. The oracle's Viewer builds a
  single ArenaSpace and hands the SAME object to Kurt and to the ScriptRuntime
  (Viewer.cs:194, :207), so `EnterArena`'s `space.Add` is immediately a collision
  surface. In the port the frontend gives the Player its own space
  (main.cpp:413, main_3ds.cpp:535) and the runtime builds its own from the
  reachable arenas in its constructor. `enterArena` therefore adds to the SCRIPTS'
  space — the one `runTick`'s geometric arena lookup reads — so a teleport-only
  arena answers the arena RULE and does NOT yet make Kurt collide with the arena no
  doorway leads to. The C#'s `TeleportMakesUnreachableArenaSolid` asserts the
  collision space; the port's version asserts the scripts' space, and the case
  says so at the line. Unifying the two spaces is a real change with its own blast
  radius (the pin, the move, the sight probes) and is NOT attempted here. Logged in
  CONTINUATION as the next item's first candidate.
* `ArenaSpace::arenaAt` answers the FIRST box containing a point; the C#'s `At`
  returns a LIST and the oracle's assertion is `Contains`. The port's pair of
  assertions (not the answer before, the answer after) is weaker than the C#'s and
  is labelled as such in the case.
* NO GOLDEN EXECUTES A TELEPORT, and none can be added: `dotnet` is gone from this
  box, so no oracle dump exists for the teleport path. Every expected value in the
  three new cases is read off the committed C# and the shipped DTI goldens, which
  is transcription, not measurement, and transcription is weaker.
* Neither opcode fires in levels 3-8 (the `unimplemented()` probe at t30000 was
  clean on this corpus before this batch and 112/173 were not in it), so the pinned
  frame is expected to be byte-identical to its predecessors. The frame published
  with this batch says so in its sidecar rather than claiming a visible change.
* `Kurt.Keeper` (`_keeper = null` in the C#'s Teleport) and FrameBlend's Kurt half
  (the `Teleports` reader) are both still deferred with their subsystems.
* `LevelView.Enter` — the `ArenaEntered` subscriber that makes a teleported-to
  arena DRAWABLE — is deferred with the level view, so the visible half of "an
  arena no doorway leads to" is still not reachable here at all.
* THE FRAME IS BYTE-IDENTICAL to batch 140's (`docs/frames/2026-11-11-teleport-kurt.png`,
  md5 6769a13731983d65cee9df02da6cff37, the same bytes as
  2026-11-11-trigger-show-and-clear.png and the three before it). Measured, not
  assumed: level 3 frame 1 has no teleport in it, so a batch that moves shipped code
  can still leave the pinned picture untouched, and saying which is which is the
