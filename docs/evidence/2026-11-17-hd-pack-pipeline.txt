THE 3DS HD TEXTURE PACK PIPELINE (docs/HD_TEXTURES_3DS_SPEC.md), 2026-11-17.
Host-side build tooling only; no 3DS code reads the pack yet (next milestone).

SOURCE, CHECKED AGAINST UPSTREAM. github.com/nautilusbits/mdk-sdl (nemo22/mdk-sdl
redirects there): README "HD textures (optional) ... upscales the game's textures
and HUD 2x with the AI upscaler Real-ESRGAN, locally on your GPU, from your copy
of the game, into a mod ... Nothing upscaled is distributed." Every release
(v0.9.0-alpha .. v1.2.6) carries only the game builds (apk, linux x64/arm64, osx,
win); the repo holds the generator (src/Mdk.Game/HdTextures/HdGenerator.cs), no
pack. So the build MAKES the pack, as upstream does.

PIPELINE. mdk_3ds/tools/build_hd_pack.sh:
  1. builds the C# oracle into the scratch tree via tests/frames/capture_oracle.sh
     if not built;
  2. runs `mdk_sdl --upscale-textures=<levels>` there: it downloads the pinned
     Real-ESRGAN (44 MB, SHA-256 checked by upstream's UpscalerSource) once and
     writes mods/hd-textures/ in the PC layout;
  3. mdk_3ds/tools/hd_pack_convert.py: flood-bleed alpha-0 colour, resample to
     power-of-two axes at most 512, ETC1A4 if any alpha < 255 else ETC1,
     `tex3ds -f <fmt> -q high -m gaussian` (mip chain built and compressed on the
     host), manifest.txt (key, format, source and output sizes, bytes, source
     hash, cap, settings).

MEASURED (level 3, RX 6600 via RADV, 16 cores):
  generate: 578 textures, 217 s, 82 MB PNG ("HD textures: 578 textures made")
  convert:  8 m 42 s; 400 ETC1A4 (each has true alpha-0 texels in its source:
            all 400 counted), 178 ETC1; 21.6 MB with chains (3D 20.3 MB, 2D 1.3 MB);
            sizes 256x512 x180, 128x512 x92, 512x512 x91, 256x256 x67, ...
  incremental: a re-run encodes 0 and keeps 578.
  deterministic: two fresh conversions of the same 12-image subset are
            byte-identical (diff -r).
  The level's linear heap has ~14-16 MB free after a load, so the pack cannot be
  resident at once: the runtime streams it (spec 4.2).
