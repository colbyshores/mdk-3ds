WHAT WAS WRONG. The PICA's RGBA8 is a little-endian 32-bit word with RED IN THE
TOP BYTE — `[A, B, G, R]` in memory — which is the same convention this backend
had already been forced to discover for the clear word (`pica::clearColour`,
pica_matrix.h, measured two runs on this same instrument). The texel expansions
never got the memo: `expandIndices` wrote the palette's `[R, G, B]` plus a forced
alpha of 255 straight into memory, so the hardware read its RED from the byte the
port had pinned to 255. Every painted pixel came back with R = 255. Green and
blue were the palette's blue and green, swapped, and the texel's ALPHA was the
palette's red byte.

WHY IT WAS NOT OBVIOUS. The alpha is the index-0 discard (`GPU_GREATER 0`), and a
discarded texel is all four bytes zero, whose alpha is zero under ANY byte order.
So the transparency kept working perfectly while every colour it let through was
wrong — the symptom looked like a palette or a combiner bug, never like a discard.
