  "emurun.sh's canary counts pure-blue pixels with no positional test, so a
   reflected canvas (determinant -1) passes `--expect hud` unchanged."

Reproduced against the commit this batch replaces, with the reviewer's own
scenario built rather than argued:

  $ git show HEAD:mdk_3ds/tools/emurun.sh > /tmp/emurun-parent.sh
  # a capture holding the marker's 11x11 block at the panel's FAR corner,
  # i.e. what a determinant -1 quarter turn paints
  $ bash /tmp/parent_verdict.sh /tmp/emurun-parent.sh
  expect    : HUD VISIBLE -- 121 canary pixels in the panel
  rc=0

  $ bash /tmp/parent_verdict.sh mdk_3ds/tools/emurun.sh      # same capture
  emurun: HUD MISPLACED: 121 canary pixels painted, but only 0
            of them inside the marker's expected rect (crop
            0,0-11,11); their bbox is (389,229)-(399,239). ...
  rc=1

The parent calls a reflected HUD VISIBLE. The child refuses it. The finding is
real, and it is the row's own acceptance command that was too weak.

Why the sign matters and a count cannot see it: `pica::canvasMatrix`
(mdk_3ds/src/render/pica_matrix.cpp:177-182) performs the panel quarter turn as
    out.x =  m.y      out.y = -m.x
Drop the minus and the linear part's determinant goes from +1 to -1: a
REFLECTION instead of a rotation. The marker keeps its size, its colour and its
pixel count and moves to the other corner of the panel. This is not a
hypothetical defect family — batch 147's word-order bug was an orientation bug
that hid behind a count for eleven runs.

2. THE EXPECTED RECT IS DERIVED, NOT REMEMBERED
===========================================================================

Inputs, all read from the shipped sources (not from a screenshot):

  kCanvasHeight = 360.0f      mdk_core/src/render/render_types.h:54
  kScreenWidth  = 240         mdk_3ds/src/render/renderer_c3d.cpp:68
  kScreenHeight = 400         mdk_3ds/src/render/renderer_c3d.cpp:69
  kSize         = 16.0f       renderer_c3d.cpp:2581 (drawDiagnostic)
  canvasWidth   = 360 * 400/240 = 600   (mdk_render_canvas_width)

canvasMatrix maps canvas (x,y) to the portrait target as
      px = (1 - y/360) * 240        py = (x/600) * 400
and the display rotates the portrait target back to the landscape 400x240 crop as
      crop_x = py                   crop_y = 240 - px
so the marker's canvas rect [0,16]x[0,16] lands at
      crop_x = 16 * 400/600 = 10.667
      crop_y = 16 * 240/360 = 10.667
Pixel centres strictly below 10.667 are columns/rows 0..10: an 11x11 block,
121 pixels. ceil() adds one column and one row of rasterisation slack, giving
the inclusive rect 0,0-11,11 declared as CANARY_X1/CANARY_Y1.

tests/scripts/emurun_harness_test.sh recomputes that number from the four
constants and fails if it disagrees with the harness's declaration, so the
expectation cannot drift from the geometry that produces it. A constant the test
cannot find is a hard failure, never a skipped check.

===========================================================================
5. WHAT THE CANARY STILL CANNOT DO (stated, not hidden)
===========================================================================

* It is a known-colour canary, not a reference diff. There is no HUD-off build, so
  nothing is subtracted; the flag proves that a draw in the canvas's own state and
  space reached the panel at the canvas's own corner. It says NOTHING about the
  HUD's own quads being correct, correctly coloured, or complete. The dial's
  fidelity is a separate question with a separate oracle (the C# renderer).
* The rect is the MARKER's, and the marker is drawn by drawDiagnostic, not by the
  HUD. A HUD that drew in the right place with a wrong matrix of its own would not
  be caught here. (The canvas and the marker share `pica::canvasMatrix`, which is
  why the marker is a fair proxy for the canvas and not a fair proxy for the HUD's
  own layout.)
* The tolerance is one column and one row (ceil). A transform error smaller than
  ~11 panel pixels is not caught. That is a rasterisation-slack choice, and it is
  deliberate: a tighter rect would red on subpixel jitter and teach the reader to
  ignore the check.
* The floor is 25 of ~121, unchanged from before this batch.
