WHY A CANARY AND NOT A DIFF
--------------------------------------------------------------------------------
A visibility verdict normally means diffing against a HUD-off frame. There is no
HUD-off build, and making one would mean a renderer switch this project does not
have and should not grow for a test. So the renderer ships a 16x16 marker in the
canvas's own pixel space, through the canvas's own matrix, texture, combiner,
tint path, cull and depth state, in a colour that occurs nowhere in the level-7
capture. An exact hit in the panel can then only have come from the canvas's draw
path — one frame, no reference, and the marker is ~110 panel pixels so a floor of
25 cannot be met by a stray edge pixel and cannot be missed by a HUD that paints.

The thing it replaced drew a white triangle over most of the clip square through
an identity matrix. It never painted, so it proved nothing; and it would have
flashed the whole panel white the moment the bug it watches is fixed.

WHAT IS LEFT, stated as the shortest true thing
--------------------------------------------------------------------------------
THE FRAME'S TAIL IS DEAD. A draw issued after `replayQueue` returns does not
reach the panel, no matter whose mesh, matrix, texture or state it carries --
including `drawRecorded`, the function that renders the scene 137 times a
frame. The canvas is the last bucket of the replay, so it is the first casualty.
The next step is the boundary between the last replayed draw and C3D_FrameEnd:
(a) reverse the bucket order in replayQueue and see whether the level's last
draws go missing instead of the HUD's; (b) read C3Di_UpdateContext /
C3D_DrawArrays in the linked libcitro3dd.a for a counter or ring that saturates
after N draws. C3D_GetCmdBufUsage() is 0.101 at the canvas draw, so it is not
the command buffer's byte size -- but that is citro3d's own view of its buffer,
not what the GPU consumed.

TWO PROCESS FAULTS THAT NEARLY PRODUCED A WRONG FINDING
--------------------------------------------------------------------------------

  its silence read as a null result.
* Probe 9's revert was a string replace that silently did not match, so probe 10
  ran with the replay still disabled and reported probe 9's result as its own.
Both were caught only because a measurement could not be distinguished from the
one before it. A probe that cannot fail is not a probe — including the probes run
to find why a probe cannot fail.
* The first eight probes read the panel with a hand-typed rectangle 22 rows too
  high. All were re-checked through panel_crop.py's imported rectangle; no
  conclusion moved, which is why this is a footnote and not a retraction.
