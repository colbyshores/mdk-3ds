VELOCITY-SCALED BUBBLE RADIUS — 2026-11-23
Owner playtest of the bubble build (6f25a4a1): transitions definitely
smoother; sprinting at a door still hitches (fixed 120-unit radius =
~180 frames at walk, ~60 at sprint closing speed).

CHANGE: radius = 120 + smoothedEyeSpeed(units/sec) * 2.5 s, cap 420,
hysteresis +40. Speed is time-normalised (|dEye|/dt, EMA 0.15) so a
single long frame cannot inflate it (validator F1: per-frame delta had
a slow-frame -> more-work feedback loop). Named constants
kBubbleBaseRadius/kBubbleLeadSeconds/kBubbleMaxRadius/kBubbleHysteresis.

TRIED AND REVERTED in the same batch: bubbling through the SECOND
arena's doorways (the tunnel's far door during room->corridor). It made
the door cluster worse (frames 771-773 = 131.6/88.1/99.5 ms vs 82/36/33
without): the next room's build starts exactly at activation instead of
during the corridor walk, where the current arena's own bubble covers
it anyway. The named-arena query overload came out with it.
