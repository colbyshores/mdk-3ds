2026-11-17  Every 3DS scene texture was sampled upside down, and the arena vanished
==================================================================================

SYMPTOM (HARDWARE and EMULATOR alike). On every level the 3DS showed no arena
-- no walls, no floor, a flat clear-colour background -- and Kurt as a black
silhouette, while objects and the HUD drew. The Linux build at the same level
and frame shows the tunnel, the lit floor and a textured Kurt
(2026-11-17-linux-level7-f600-reference.png, level 7 frame 600, 400x240).

BISECTION (EMULATOR, Mandarine r1.2.1 md5 0d2adab6..., DISPLAY=:99, level 7,
runtime switches read from sdmc:/3ds/mdk/rdebug.txt, seeded with the new
`emurun.sh --seed-sdmc <dir>`):
  - `flat` (scene draws use a constant colour per pass instead of the texture):
    the arena's full geometry appears, red walls, green gate, blue blended
    parts (2026-11-17-emu-level7-rdebug-flat.png). Geometry, transforms,
    culling and depth are fine.
  - `noalpha` (alpha test off; since removed, it fought a pinned single-writer
    check): the arena appears solid BLACK -> its sampled texels were (0,0,0,0).
  - `texlog` (describe index textures at creation): every palette full (254
    non-black entries, all opaque) and every texel array populated -> the data
    entering the expansion is right.
  - the draw sample log (drawlog.txt, extended with frame and the UV uniform):
    arena draws frame=0, uv transform e.g. (1.0, 0.5977, 0, 0) for a 256x306
    texture padded to 512 rows.

CAUSE. The PICA samples t = 0 at the LAST row of a texture's memory. The
expansion writes image row 0 into the FIRST rows (pica::textureTexelIndex,
y = 0 first), and the vertex shader passed t = v*scaleY + offsetY straight
through. So every scene texture was read upside down, and a texture whose
height is not a power of two read its transparent padding (rows 511..206 of a
512-row buffer holding 306 image rows) -> alpha 0 -> discarded: the arena on
every level, and Kurt's frames. Power-of-two textures were merely flipped,
which a lava or noise texture does not show. The canvas is exempt and correct
on hardware: its projection inverts y on the panel, cancelling the same
inversion (the HUD reads "100" upright in every hardware capture).

FIX. Scene draws upload the UV uniform as (scaleX, -scaleY, offsetX,
1 - offsetY), via pica::sceneUvFromTop (rule, measurement and the canvas
exemption documented there), pinned by tests/scripts/pica_matrix_tests.cpp
testSceneUvRunsFromTheLastRow (v=0 reads image row 0, v=1 reads the last image
row, not padding; a frame offset moves down the image).

RESULT (EMULATOR): 2026-11-17-emu-level7-scene-uv-{before,fixed}.png. Kurt is
textured, and the tunnel walls, the gate, the far objects and the ceiling beams
are drawn in the Linux layout. NOT YET MATCHING Linux: the lit floor under Kurt
is absent even with `flat` (so it is geometry, not texture), and the scene is
darker. Those are the next slices. HARDWARE: not run (the console is lent to
another project); the hardware evidence that motivated this is the level-5/7
captures in 2026-11-17-hw-loop-stable-first-hardware-results.txt.

GATES: make -C tests/scripts 856 PASS ("All cases match the oracle."),
tools/check.sh ALL GATES PASSED, hw_cycle_selftest 18/18. `emurun --expect hud`
is still rc 7 with the same pre-existing 12/43 canary verdict.


ADDENDUM, SAME DAY: THE FLOOR WAS CULLED (the Solid pass's cull mode)
--------------------------------------------------------------------

After the UV fix the lit floor under Kurt was still missing, even with `flat`,
so the floor's triangles were being rejected. Two temporary single-change
builds (EMULATOR, level 7; reverted, never committed):
  - culling OFF for every draw: the frame matches the Linux reference (the
    tunnel, the lit floor, the far objects);
  - depth test OFF: no improvement.
GPU_CULL_BACK_CCW, chosen by reasoning about the camera's handedness and marked
in its own comment as needing a look, was culling the FRONT faces. Visible faces
reach the PICA CLOCKWISE. With GPU_CULL_FRONT_CCW the frame differs from the
culling-OFF frame in 0 of 109,312 crop pixels, so nothing visible is culled.
The permanent build differs in 251 pixels, all inside Kurt's sprite bbox: his
idle animation frame at capture time. The picture is not mirrored against Linux
(Kurt's raised arm, the HUD corner and the floor patch agree), so the enum, not
a mirror, was the defect.

FIX: kSolidCull = GPU_CULL_FRONT_CCW (01_types.inc), used at every site
(begin_frame install, the per-draw pass selection, the post-diagnostic
restore). No host test pinned the cull mode; this is measured, not reasoned.

SIDE BY SIDE (left Linux, right 3DS in Mandarine): levels 3, 5, 6 and 8 now
agree in geometry, textures, lighting, Kurt and objects
(2026-11-17-cull-fix-side-by-side-L{3,5,6,8}.png). REMAINING: (1) the sky /
panorama is not drawn on the 3DS (a full-screen per-pixel pass on Linux; the
PICA200 has no fragment shader); (2) the (0,0,255) canvas canary is drawn in
every build, release included. HARDWARE: not run (the console is lent out).


ADDENDUM 2, SAME DAY: THE SKY, AND TEXTURE WRAP / FILTER
--------------------------------------------------------

THE SKY. The 3DS never drew the panorama (mdk_render_set_panorama was a stub,
and the PICA200 has no fragment shader for the oracle's per-pixel pass). The
panorama is also 1800 columns, over the PICA's 1024 texture limit, so the
frontend's index texture could not even be created. New
mdk_core/src/render/sky_dome.{h,cpp}: a sphere tessellated in the oracle's
(column, row) space, about 32 columns x 30 rows per cell. Each vertex's
direction is the inverse of panorama.hlsli's mapping, which is linear in
azimuth and elevation. The columns are cut into <=1024-wide index slices,
index 0 is remapped to the nearest palette colour (the sky has no discard;
0 texels needed it on the shipped levels), and flat caps take
top_colour/bottom_colour. Trig through the shared LUT (R6). Host test
(tests/scripts/sky_dome_tests.cpp, against a libm copy of the oracle formula):
worst column 0.0002 and worst row 0.0042 of a panorama cell over every band
vertex; slices fit and cover every column once. The 3DS frontend builds it at
level load and queues it first each frame as DoubleSided, centred on the
camera; solid geometry, drawn in the earlier pass bucket, occludes it through
depth. Log line, e.g. level 3: `sky: 1804x360 wrap=1800 horizon=240 offset=300
-> 2 slices, 8208 vertices`. Side by side: 2026-11-17-sky-dome-side-by-side-L{3,5,8}.png.

TEXTURE WRAP AND FILTER. Nothing set them, so textures took C3D_TexInit's
defaults. The world's tiled surfaces (rdebug `uvlog`: every tiling draw of
level 3, 45 of them, is 256x256; level 7 has none) smeared into one edge texel
under clamp: level 3's ground. Now NEAREST/NEAREST (the oracle looks up one
index per texel), and GPU_REPEAT on any axis whose real size equals its padded
size (exact: no padding to wrap through), clamp otherwise. Level 3 side by side:
2026-11-17-wrap-repeat-side-by-side-L3.png.

GATES: make -C tests/scripts 857 PASS (new: SkyDome), "All cases match the
oracle."; tools/check.sh ALL GATES PASSED (incl. audit_arm11_math and
gates_core_parity after listing sky_dome.cpp in mdk_linux/CMakeLists.txt).
EMULATOR evidence only.


ADDENDUM 3, SAME DAY: THE CANARY LEAVES RELEASE FRAMES; THE HUD ROW IS GREEN AGAIN
---------------------------------------------------------------------------------

THE CANARY. The (0,0,255) canvas marker was drawn in every build: a blue
square in the top-left of every frame a player would see. drawDiagnostic now
returns at once unless sdmc:/3ds/mdk/canary.txt exists (read once).
`emurun.sh --expect hud*` seeds that file in the lane before launch, so the
verdicts are unchanged. The eye loop's call stays unconditional (the pinned
`eye-loop-statements-unconditional` check). A plain run: 0 pure-blue pixels in
the panel (2026-11-17-emu-level7-1to1-no-canary.png).

WHY `3ds.hud-canvas` (d1, ledger-done) WAS FAILING ITS OWN ACCEPTANCE.
`emurun.sh --expect hud` had been rc 7 (`HUD INK NOT UNIQUE: 12 of 43`), with
an explanation (the death skull) that cannot apply to a health-100 run. The
measurements:
  1. Mandarine's default layout scales the screens to the window. The window
     drifted (c5a22d7), and every capture's top screen was 427x256, a 1.067x
     linear-filtered upscale. Every verdict rectangle is in 400x240 panel
     pixels, so the HUD's ink landed 7% past its rect. emurun now sets a
     custom layout (layout_option=6, top 400x240, bottom 320x240) and
     filter_mode=false: one captured pixel per 3DS pixel.
  2. tools/panel_crop.py find_panel believed a found origin only if half the
     panel was non-black: true while the 3DS drew a clear colour and a few
     objects, false once the scene drew (a dark tunnel). It fell back to stale
     constants and read the wrong rectangle, giving 0 canary pixels while the
     capture held all 121. It now requires >= 32 non-black pixels along the
     found top row and left column (a lone 11x11 synthetic marker still
     cannot anchor it; a real frame shows 96 and 84).
RESULT: `DISPLAY=:99 mdk_3ds/tools/emurun.sh --expect hud` rc 0:
`HUD MARKER VISIBLE -- 121 canary pixels in the panel, 121 inside`,
`HUD INK -- 165 of 165 HUD-palette pixels inside crop`.
