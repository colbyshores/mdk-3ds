why an A/B that moves nothing is still the measurement. The parent left citro3d's
       initialiser blend in place -- C3D_AlphaBlend(ADD, ADD, SRC_ALPHA,
       ONE_MINUS_SRC_ALPHA, SRC_ALPHA, ONE_MINUS_SRC_ALPHA), measured from the
       linked libcitro3dd.a by the builder and independently by the reviewer --
       and this build writes the oracle's replace pair for an unblended pass.
       Two different register states agree pixel for pixel across 96000 pixels
       only if every visible fragment has alpha 255. So the pair MEASURES what
       the code reading had only claimed: the palette expansion forces 255 on
       every non-zero index (renderer_c3d.cpp:1267), and the flat-colour path
       carries the material alpha, which is 1.0 for a palette colour and the DTI
       glass alpha only on a Blended pass -- where the oracle multiplies it in
       (shaders/palette.hlsl returns `float4(palette...rgb, 1.0) * colour *
       input.colour`). That closes review-3 F1's live worry: there is no sub-255
       fragment alpha hiding in this scene, on this pass or on `Pass::Blended`.
