1. F1 (Medium, CONFIRMED, FIXED): --secs, THE OTHER CALLER-SPELLED FIELD
--------------------------------------------------------------------------------

`emurun.sh:207`  `MAX_SECS=3600`, in the measurements block beside MAX_FRAMES.
Four digits as a RELATION and not a taste: the two constants describe one run —
a settle window produces frames — so a legal `--secs` must never be able to
produce a frame count `frame_floor` then refuses to evaluate. At the ~60 fps the
file already assumes when it calls MAX_FRAMES "about 4.6 hours", an hour of
settle is ~216 000 frames, inside MAX_FRAMES. The test checks `MAX_SECS*60 <=
MAX_FRAMES` instead of trusting the sentence. Past an hour the caller is not
waiting for a run, it is hanging the harness, which is the failure mode
review-5 F2 exists to prevent.

`emurun.sh:251`  the `--secs` arm now runs `need_value` then
`decimal_measurement "$2" "$MAX_SECS"` and refuses at 2 BY NAME, at parse time,
in front of everything expensive — the `--min-frames` shape, deliberately
identical to it.

`emurun.sh:910`  `END=$(( $(date +%s) + 10#$SECS ))`. The bound does NOT make
the base safe: `--secs 0045` is legal (padding is a spelling, not a
contradiction — batch 159/160's ruling) and must settle 45, not 37. `10#` is
evaluable because the parse-time guard proved the field a non-empty decimal, and
the test pins that the guard precedes the line.

After the fix, same lift:

    --secs 45     rc 0   WINDOW=45
    --secs 010    rc 0   WINDOW=10     <-- the base, fixed
    --secs 0045   rc 0   WINDOW=45     <-- the base, fixed
    --secs 08     rc 0   WINDOW=8      <-- a decimal eight, not an abort
    --secs 3600   rc 0   WINDOW=3600   <-- the bound is inclusive
    --secs +45    rc 2   "--secs requires a decimal 0..3600, got [+45]"
    --secs 4s     rc 2   named
    --secs 3601   rc 2   named
    --secs 99999  rc 2   named
    --secs ""     rc 2   named         <-- the unset-variable wrapper

WHAT THE FIX DOES NOT DO, stated rather than hidden: `--secs 08` is now
ACCEPTED and means 8. Refusing a padded-but-consistent value would be a spelling
check wearing a relation's clothes (batch 160's own ruling, applied the other
way). The other caller-spelled flags were assessed and left alone: `--grep`,
`--shot` and `--expect` are strings used as strings, and `--display` is a number
used as a string — a wrong one fails loudly at the `xdpyinfo` check (rc 2, named)
rather than silently measuring something else.

2. F2 (Medium, CONFIRMED, FIXED): A PRESENCE CHECK THAT PIPES IS A RACE
--------------------------------------------------------------------------------

`tests/scripts/emurun_harness_test.sh:58` — one helper, `lift_contains`,
replaces all FOUR piped presence rows (lines 389, 391, 395, 628 of the parent
file). The reviewer found one of the four; the class is the same one batch 158
closed for "is this a number" — several spellings of one question, one of them
wrong, and the fix is one spelling.

    lift_contains() { case "$1" in *"$2"*) echo 1 ;; *) echo 0 ;; esac }

No pipe, no second process, nothing to race, and the quoted half of the pattern
is literal, so `canary_stats()` matches itself and not a class. Measured with the
new form: 0 of 200 red on the 34 443-byte payload that reds 15 of 200 piped.

Two rows pin it beyond the four it replaces:
  * a 200-run determinism row on the REAL block — on the piped form that is a
    ~1e-25 event at the measured rate, so it is a pin and not a formality;
  * a shape row: this file must never contain a piped early-exit grep again
    (`grep -c 'grep -[q]'` on itself — the bracket is what stops the checking
    line matching itself). A lifted block is a shell variable; the file now says
    so once, in the helper, instead of four times in four rows.
