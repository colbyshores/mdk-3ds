## Findings

1. **The mip glitch is a PICA200 hardware quirk.** In a non-square ETC1 texture, the GPU
   draws part of the level whose short side is 16 texels from the next level's tiles.
   Tall textures show a half-size copy in the lower-left. Square ETC1 and every other
   format are fine; the emulator is fine. Fix: stop non-square ETC1 chains at that level
   (`mdk::pica::mipLevelsSampled`). Cache flushes, nearest-mip, cache clears and level
   counts were all ruled out first. Found with a standalone hardware probe, not the game.
2. **Doorway hitches were first-use work on core 0, not streaming.** The streamer had 0
   waits. Each door had its own cause: a room's mesh built on entry (the bubble didn't
   look past a short corridor), object textures read on the main thread, an effects warm
   that never re-armed after its arena was released, a one-time shadow readback, and a
   linear texture-name scan. Fixed one by one, measured per door.
3. **The slow frames are CPU-bound.** The GPU takes 13–15 ms a frame. In L8 combat the CPU
   takes about 28 ms: draw submission for both eyes (`C3D_FrameEnd`) 8.2 ms, objects 7.1,
   scripts 5.2, Kurt's firing 3.3, effects 1.2–3.6. Worst one-second window: 20 fps. This
   is the next performance target, submission and objects before scripts.
4. **VRAM placement doesn't pay here.** Strips and sky in VRAM saved 0.6 ms of GPU time and
   under 1% of the frame. Not kept (parked on a throwaway branch in case linear memory
   runs out). Inside a frame, `C3D_TexInitVRAM` only queues the copy while tex3ds frees the
   staging buffer, which is why VRAM textures used to "fail".
5. **"Heap growth per reload" was fragmentation.** In-use bytes were flat. Menu fonts kept
   by statics and run-long renderer tables first grown during a level left blocks in the
   level's region, so the heap top sat about 5.5 MiB higher on every reload. Fonts now
   belong to the level; the tables are reserved at boot. On the console with HD on, a
   ~5 MB step after the first reload remains (suspect: the HD copies table is never pruned).
6. **Load time lived in parsing.** A build-time binary texture-name index (with a stamp and
   a fallback to the text parse) cut 2.5 s to 66 ms; reading the manifests in one read saved
   about a second more; the light-rig scan now overlaps the worker's reads (−1 s).
7. **Sound effects all fit at level load.** Decoding every effect behind the loading screen
   uses at most 68% of the 2 MiB DSP buffer and adds about 0.16 s; simpler than a worker
   job with rules for late sounds.
8. **The 3D was flat because the eyes were parallel.** There was no off-axis shift, so zero
   parallax sat at infinity. Now each eye's frustum is shifted (like the C#, Linux and
   Forsaken), with defaults sized in pixels and two START-menu rows to tune it.
9. **ATM screenshots preceded the appliance's hard hangs.** ATM's log shows a screenshot
   commit, then nothing until the power-on, about 4 s later. Over 30 runs without
   screenshots, no hang. Use the game's own frame readback for pictures.
10. **Build caches copied between worktrees go stale.** Their dependency files named the
    other worktree's paths, so a header change didn't rebuild a host tool, which then
    crashed with "stack smashing". Never copy `build*/` between worktrees.
11. **Opcode coverage vs upstream's C++:** both dispatch the same 238 opcodes; four were
    only partly implemented here (pendulum 226, comm screen 133, dog tethers 242, box
    sprites 159) and now match the C# 1.2.6 byte for byte. Opcode 5 is implemented nowhere.

## Still open

- L5 MUSE_1 doorway: an intermittent ~200 ms script stall, seen only with Kurt in noclip.
- The console's ~5 MB heap-top step after the first reload with HD on (finding 5).
- Stereo defaults: the owner tunes the two rows; their values become the defaults.
- HOME and lid sleep have not been tested on a console since the streaming worker changed.
